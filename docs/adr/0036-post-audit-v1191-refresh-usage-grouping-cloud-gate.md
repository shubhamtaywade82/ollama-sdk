# ADR 0036: Post-audit v1.19.1 refresh — re-pin 36a6e99, usage model grouping, ShowResponse prompt provenance, the 0.40.5 cloud-model gate, and pin-provenance unification

**Status**: Accepted
**Date**: 2026-10-22
**Context**: The daily audit against the v1.19.1 baseline (`aa82b50`) again claimed "zero upstream drift since d9b8601, 100% parity, no action needed." Independent verification (raw content diff of upstream `docs/openapi.yaml` vs the pin, never trust the report) found the headline false: two upstream commits had landed — `2476d5e` (2026-10-16, "docs: add model grouping to cloud usage") and `36a6e99` (2026-10-17, "api: populate show renderer/parser fields and add template_source") — plus two repository-internal defects the audit missed.

## Context

Four findings drove this refresh, each verified at the source before any change:

1. **Real upstream drift (additive).** `GET /api/usage` gained a `group_by=model` query parameter with two new schemas — `UsageGroup` (UsageMetrics + a required `model`) and `UsageSummary` (UsageMetrics + optional `groups`, up to 10 entries ranked by usage or request count, and a `remainder` roll-up). `UsageResponse.totals` changed from `UsageMetrics` to `UsageSummary`, `UsageBucket` composes `UsageSummary`, and the response echoes the selection in a new `group_by` field. Independently, `ShowResponse` gained `renderer`, `parser`, and `template_source` (prompt provenance: `renderer_parser` | `renderer` | `parser` | `harmony` | `go_template` | `gguf_chat_template` | `none`). Both are documented on the live docs pages (`docs.ollama.com/api-reference/show-model-details` documents the three new show fields), so they are parity obligations, not optional niceties.

2. **The documented-but-unimplemented 0.40.5 cloud-model gate.** Since the 2026-10-16 System One cloud launch (ADR 0034), `contracts/overlays/systemone.yaml`, `docs-site/guide/system-one.md`, and `client.ts`'s own JSDoc all stated that cloud models (`clef:cloud`) require "Ollama >= 0.40.5 or the hosted https://ollama.com endpoint" and that the runtime enforces version constraints automatically. Only the blanket operation-level `minOllamaVersion: 0.35.0` existed in the IR and the generated runtime. The model-dependent floor was documented fiction — the same failure class ADR 0035 fixed for `retryAfterMs`, and the exact class the 1.19.0 audit caught being claimed without implementation.

3. **Stale pin provenance in `docs-index.json`.** The index's `pinnedSha` recorded the upstream file's git **blob** SHA (`2a9ffe39…`, the 2026-10-15 state) and had not been updated when the pin moved to `d9b8601` on 2026-10-16. Nothing consumed the field, no test covered it, and the two files tracked *different kinds* of identifier (the spec header records commit SHAs), so the staleness was invisible to every gate.

4. **The recurring display-artifact trap.** During verification, `grep`/`sed`/`diff` output showed what looked like nine "bracket-eaten" corrupted literals (`required: odel]`, `enum: , 7d, 30d]`, `enum: our, day]`) in the upstream file and in our pin. Character-code inspection proved the files were clean — the terminal output pipeline strips ANSI-like sequences (`[m` inside `[model]`, `[h` inside `[hour, day]`, `[24h`) from displayed text. This is the **second** time this exact artifact has been mistaken for upstream corruption; the 1.19.0 wave recorded the first ("our own Bash display artifact eating CSI-style sequences") and retired the 2026-10-07 repair deviation on that basis. The lesson is now written down where audits happen, and the new pin-consistency test asserts structurally (regex on file content) rather than visually.

## Decisions

1. **Re-pin to `36a6e994d2f6c4ab94b3555185154d069e5dba87`** — the state of upstream main since 2026-10-17; `git show 36a6e99:docs/openapi.yaml` reproduces the pinned body byte-for-byte, so the pin is verifiable without network access to GitHub's commit API. The refreshed header documents both upstream commits. The single intentional structural deviation is retained unchanged: `ModelSummary.details.families` typed `[array, null]` (nil Go slice serialization). No literal "repairs" are carried — upstream serves the file clean.

2. **Model grouping surfaces on the typed client, mirroring `range`/`scope`.** `UsageRequestOptions` gains `groupBy?: UsageGroupBy` (`'model'`, the only documented value), serialized as the `group_by` query parameter — snake_case on the wire, camelCase at the SDK boundary, exactly like the sibling parameters. The generated layer picks up `UsageGroup`/`UsageSummary` and the widened `totals`/`buckets`/`group_by` echo automatically from the re-normalized IR; `src/types.ts` re-exports the two new models. `UsageSummary` extends `UsageMetrics`, so the `totals` widening is read-compatible for existing consumers.

3. **The 0.40.5 cloud-model gate lives in `OllamaClient.systemOne`, not the IR.** The constraint is request-dependent (only cloud models, only local servers) — it cannot be expressed as a static operation constraint, and the generated runtime is off-limits to hand edits. The wrapper now consults `isCloudModel(model)` (the `:cloud` suffix the upstream docs use for cloud model names) and, for local-mode clients, probes `/api/version` through the normal failover machinery (cached per client instance, reset on probe failure so a later gated call retries), comparing with `compareOllamaVersions` — numeric component-wise, mirroring the generated runtime's private comparator, so `'0.9.0' < '0.40.5'` ranks correctly rather than lexicographically. Below the floor it throws the new typed `OllamaCloudModelVersionError` (code `cloud_model_version`, carrying `model`, `serverVersion`, `minRequiredVersion`) **before** any request is sent. Hosted `ollama.com` endpoints never gate (they always front cloud models), non-cloud models never gate, and a failed probe fails open — matching the runtime's `'auto'` `enforceVersion` policy, letting the server's own response be the next signal. The low-level `client.native.systemOne` path deliberately bypasses the gate, same as it bypasses all wrapper ergonomics; the docs promise now scoped to `OllamaClient.systemOne`, where the docs point.

4. **Pin provenance unifies on commit SHAs, enforced by a test.** `docs-index.json`'s `pinnedSha` now records the same upstream commit SHA as the pin header's first line, and `pinnedAt` equals the header's pin date. New `test/contract/pin-consistency.test.ts` asserts header/index agreement (plus 40-hex formats and on-disk existence of every indexed source path), so an index that lags a refresh can no longer hide behind a passing build. The blob-SHA convention is retired with a note in the index's `$comment`.

5. **Public surface grows by the minimum the features need.** Root exports added: `UsageGroupBy`, `UsageGroup`, `UsageSummary` (types), `OllamaCloudModelVersionError`, and the gate primitives `CLOUD_MODEL_SUFFIX`, `CLOUD_MODEL_MIN_OLLAMA_VERSION`, `isCloudModel`, `compareOllamaVersions` (next to the existing System One constants — callers building their own pre-flight checks need exactly these). Nothing is removed; `totals` widens compatibly.

## Consequences

- Version 1.20.0 (minor): new upstream-documented surface (typed fields, new schemas, `groupBy`) plus a behavior change that is additive-strict — a misconfigured local-server-plus-cloud-model combination that previously produced a server-side failure now throws a typed client-side error before the round-trip.
- Tests: 14 net-new. Four IR-content assertions (`test/contract/generated.test.ts`) pin the new schemas into the committed IR; four `groupBy` behavior tests (`test/usage-balance.test.ts`) cover query-string composition and the grouped/ungrouped response shapes; six cloud-gate tests (`test/system-one-matrix.test.ts`) cover the rejection (typed error fields, zero wasted round-trips), the exact-floor pass, model-dependence (same old server, local model passes), hosted-endpoint bypass, probe-failure fail-open, and both per-client caches holding; six pin-consistency tests make the provenance invariant permanent, including a guard that the header documents the current refresh's features.
- Docs: the system-one guide's "0.40.5+ for cloud models" warning box is now true in code, not just in prose; `client.ts` JSDoc for `systemOne`/`usage` describes the gate and grouping; the CHANGELOG carries the 1.20.0 entry.
- Declined alternatives, with reasons: (a) expressing the 0.40.5 floor as a second IR constraint — operation constraints are request-independent by construction, and the generated runtime is not hand-editable; (b) gating in the generated `NativeApi` layer — same non-editability, and the ergonomic wrapper is where the docs promise lives; (c) `strict`-style hard failure when the version probe fails — would break the established `'auto'` fail-open contract for a constraint the server can enforce itself; (d) "repairing" the phantom corrupted literals — they do not exist; repairing them would diverge the pin from upstream text for no machine benefit.
- Watch item carried forward, not acted on: upstream commit `efabf6bc` ("anthropic: surface errors after streaming starts") makes the server emit Anthropic-style error events mid-stream, while the live docs still list streaming `error` events as unsupported and the pinned MDX matches the docs. The contract rule is to pin what the *documentation* says; when the docs row flips, that is the signal to re-audit the Anthropic bridge.
